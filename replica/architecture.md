# Architecture: Aura v2 (a parity rebuild of Aura's core features)

Built from `replica/recon.md` and `replica/features.csv` (2026-10-10).

**Headline decision: keep Aura static.** The pack's default stack assumes a SaaS
product with users, payments and email (Next.js + Postgres + auth + Stripe). Aura
has none of those. It is a static player fed by data files that CI regenerates,
and that is why it costs nothing to run and survives with no maintenance. The
rebuild keeps that shape. It replaces the 1850-line single file with typed
modules and hardens the parts that break (playback, caching, the proxy).
There is one optional database, for cross-device favourites only.

## Stack

| layer | choice | why |
| --- | --- | --- |
| web | **Vite + TypeScript + Preact** (no router; views are state) | tiny runtime (~4 kB) for weak TV boxes; typed modules replace one 1850-line file; Vite gives content-hashed assets for free |
| styling | plain CSS with custom-property tokens (from `/replica-design`) + a `.tv` 10-foot scale | already token-based; Tailwind adds nothing for one app with a fixed design |
| playback | **hls.js 1.5.x, bundled** (not CDN), native HLS fallback on Safari/iOS | bundling removes the CDN fetch at first play and a failure mode on flaky TV networks |
| data | **static JSON** generated by the Python pipeline: `channels.<hash>.json`, `epg.<hash>.json`, `manifest.json` pointing at the current hashes | no DB needed for a read-only lineup; hashed names end the stale-cache problems seen in the Android WebView |
| device state | `localStorage` behind one typed `store.ts` with a schema version + migration | same keys as today, so v1 users keep favourites on upgrade |
| database | **none for parity.** Optional: Supabase Postgres for favourites/history sync (see `schema.sql`) | only add it if "same favourites on phone and TV" is wanted |
| auth | none for parity. Optional: Supabase anonymous auth + a 6-digit device pairing code | no passwords on a TV remote |
| payments | none | free app over free-to-air streams |
| email | none | no accounts |
| edge | **Cloudflare Worker** (keep `proxy/worker.js`), hardened: host allowlist + per-IP rate limit, and `/log` gets a shared token + size cap | the only server-side code; currently an open proxy |
| jobs | **GitHub Actions cron** (keep): weekly refresh, 6-hourly EPG, Pages deploy, APK build, log ingest | free, already working, versioned with the data |
| pipeline | Python 3 + `tools/m3u` (keep); `build.py` emits JSON + manifest instead of `channels.js` | proven health checker; no reason to rewrite |
| hosting | **GitHub Pages** (keep), building `dist/` with Vite in the Pages workflow instead of uploading the repo root | stop publishing `logs/`, `scripts/`, playlists twice |
| mobile / TV | **keep the WebView shell** (`android/`). Later, a could-have: a native Media3/ExoPlayer player behind a JS bridge for HLS reliability on old boxes | one codebase; the web app updates without new APKs |

## Schema

Tables: **0 for parity**, 3 optional (sync). Access rules: Postgres RLS (optional
part only). The real "schema" is the data contract between the pipeline and the app.

### Data contracts (generated files; validate in CI with JSON Schema)

```ts
// manifest.json (tiny, short cache): which data files are current
interface Manifest { version: 2; generated: string /* ISO UTC */;
  channels: string /* "channels.3f9a1c.json" */; epg: string; }

// channels.<hash>.json (immutable, cache forever)
interface Channel {
  num: number;          // stable display number, unique (CI asserts uniqueness + stability across refreshes)
  name: string;         // display name, quality suffix stripped at build time
  quality?: 'SD'|'HD'|'FHD'|'4K';   // replaces the isHD() regex on name
  url?: string;         // HLS m3u8, https only
  yt?: { id: string; live: boolean };   // YouTube-sourced channel (replaces yt/ytlive)
  logo?: string;
  categories: string[]; // replaces ";"-joined group; first = primary
  lang: Lang;           // one of 14 values
  tvgId?: string;
  flags: { proxy?: true; geo?: true; freeDish?: true };   // replaces px/geo/fd
}
// exactly one of url | yt is set (CI check)

// epg.<hash>.json (immutable)
interface Epg { generated: string; window: [number, number];   // epoch seconds UTC
  channels: Record<string /* num */, [start: number, end: number, title: string][]> }
// CI checks: per channel sorted by start, end > start, no overlaps
```

### Device state (`localStorage`, key `aura:v2`, one JSON blob)

```ts
interface DeviceState { v: 2; favs: number[]; hist: number[] /* max 8, MRU */;
  last?: number; vol: number /* 0..1 */; muted: boolean; proxy?: string; }
// migration: read stb_favs, stb_hist, stb_last, stb_vol, stb_muted, aura_proxy once, then write aura:v2
```

### Optional sync tables: `replica/schema.sql`

`devices`, `favourites`, `watch_history` keyed by Supabase `auth.uid()`, with RLS
`user_id = auth.uid()`. Only build this if cross-device sync becomes a goal.

## API

There's no app server. The "routes" are static resources, Worker endpoints and URL flags.

| method path | does | who | input | output | flow |
| --- | --- | --- | --- | --- | --- |
| GET `/webstb/` | app shell (hashed JS/CSS) | anyone | `?tv=1` 10-foot mode, `?app=1` play-all (shell), `?proxy=` override, `?diag=1` | HTML | all |
| GET `/webstb/data/manifest.json` | current data file names | app | — | `Manifest` (`Cache-Control: no-cache` via fetch option) | F01, F07 |
| GET `/webstb/data/channels.<hash>.json` | lineup | app | — | `Channel[]` | F01–F06, F10 |
| GET `/webstb/data/epg.<hash>.json` | guide | app (lazy, after first paint) | — | `Epg` | F01, F07, F08 |
| GET `<worker>/?url=<enc>` | CORS proxy; rewrites HLS manifests so variants + segments route through it | app (px channels; fallback retry) | upstream URL, **must match host allowlist** | stream bytes + CORS | F01, F09 |
| OPTIONS `<worker>/*` | CORS preflight | browsers | — | 204 | F01 |
| POST `<worker>/log` | forward a diag report to the repo as `repository_dispatch` | app + Android shell, **with `X-Aura-Log` token, ≤ 8 KB, rate-limited** | `DiagReport` JSON | 204 / 4xx | F13 |
| JS bridge `AuraShell.diag/log/info` | native log + device info | page inside Android shell | string | string | F13 |
| *(optional)* Supabase REST `favourites`, `watch_history` | sync | signed-in device (RLS) | rows | rows | F06 |

Webhooks in: `repository_dispatch: aura-log` → `log-ingest.yml`.
Webhooks out: Worker → GitHub REST `POST /repos/gnaidu05/Iptv/dispatches` (own token, official API).

Jobs:

| job | schedule | does |
| --- | --- | --- |
| `refresh.yml` | Mon 05:00 UTC + manual | health-check pool → playlists → `build.py` → channels JSON + manifest → EPG rebuild → commit → deploy |
| `epg.yml` | every 6h | `build_epg.py` → epg JSON + manifest → commit → deploy |
| `pages.yml` | push to main (ignores `logs/**`) | **new:** `npm ci && vite build` → upload `dist/` only |
| `android.yml` | push to `android/**` | APK → `apk-latest` release |

| `deploy-proxy.yml` | manual | `wrangler deploy` |

## The parts that bite

- **Time zones.** All EPG times stay epoch seconds in UTC, and the client formats them in local time. Day tabs must use local midnight and not UTC, or India (UTC+5:30) users see the "Today" tab start at 05:30. India has no DST, but users abroad do, so test the day split around a DST change.
- **Caching / stale code.** This is the source of the recent WebView reload-loop commits. Fix it structurally: hashed immutable assets, a no-cache `manifest.json`, and an app-version check that reloads once (never in a loop, guarded by a sessionStorage flag). Drop the Android `clearCache` hack once it's in place.
- **Races.** Fast zapping starts overlapping tunes. Each tune gets a token, late callbacks from a stale token are ignored, and `hls.destroy()` runs before the next attach. This is the `settled` flag today, but it's per-closure and not global.
- **Idempotency.** `log-ingest` may get the same dispatch twice. Name files by report id (client-generated UUID) instead of timestamp+random so duplicates overwrite.
- **Rate limits / abuse.** The Worker is an **open proxy** today (any `url=`), and `/log` lets anyone create commits in the repo. Add a host allowlist generated from `channels.json` px hosts, per-IP limits, a log token and a size cap.
- **Free-tier limits.** Workers free tier allows 100k requests/day, and every HLS segment through the proxy counts. Keep px channels a minority and prefer direct play (already the case: 758/792 play direct).
- **Autoplay.** Browsers block unmuted autoplay without a gesture. Keep the boot "Start watching" tap on web. The Android shell can set `mediaPlaybackRequiresUserGesture=false`.
- **Performance on TV boxes.** 868 cards plus SVG animations is too much for weak boxes. Virtualize the grid as well as the EPG, and keep the TV list mode as the default on `?tv=1`.
- **Search.** This is client-side over ~900 names. Normalize case, diacritics and quality suffixes, and match Hindi/Latin names with a small alias table from the pipeline. No search service is needed.
- **Mixed content / CORS.** HTTPS only. CI must keep the "CORS-verified" bucket honest by checking manifest, variant and first segment, as it does today.
- **Channel number stability.** Favourites and history store `num`. If the refresh renumbers channels, everyone's favourites silently change. CI should assert that existing channels keep their numbers (key by tvgId/normalized name).
- **GDPR / privacy.** Diagnostics are committed to a **public** repo. Strip IPs and device identifiers, and keep only the model, OS version and timings.

## Build order

1. **Vertical slice.** Boot (S01) → grid of channels from `channels.json` (S02, no hero/tabs) → player with hls.js, tune/no-signal (S07). Tables: none. Routes: shell, manifest, channels, Worker `/?url=`. Proves Vite build + Pages deploy + hashed data + playback on desktop, phone and the Android shell.
2. **Must-haves:**
   - *launcher:* hero (S03), category tabs and the India ⭐ split (S02), now/next on cards (epg route).
   - *player:* zap ←/→, back, proxy fallback, buffering (S07).
   - *navigation:* D-pad zone focus manager as one module (rail/tabs/tools/grid/player).
   - *state:* `store.ts` with v1 → v2 migration (favs, last).
   - *android:* shell loads the new build, D-pad mapping unchanged.
   - *pipeline:* `build.py` → JSON + manifest + JSON Schema validation, plus number-stability check. Pages builds `dist/`.
3. **Should-haves:** search (S05), language menu (S04), HD filter, sort, number entry, recents, full EPG timeline (S06, virtualized), mini guide (S08), surf card, volume/mute, fullscreen, TV list mode (S10), Free Dish row, Worker hardening, log dedupe/prune. **Then could-haves:** YouTube channels, proxy setting + help (S09), diagnostics overlay (S11), hero preview video, optional sync (`schema.sql`), native ExoPlayer bridge.
4. **Fixes from replica-entrepreneur:** *(after it runs)*.
